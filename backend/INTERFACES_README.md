# Интерфейсы и структура проекта 

Осталось реализовать всю эту темку

### 1. Интерфейсы репозиториев (`internal/repo/interfaces.go`)
- **UserRepo** - работа с пользователями (создание, получение, обновление, профиль, баланс алмазов)
- **LevelRepo** - работа с уровнями/уроками (список, детали, фильтрация по сложности/теме)
- **QuestionRepo** - работа с вопросами (получение, варианты ответов)
- **AttemptRepo** - работа с попытками прохождения (создание, шаги, статусы)
- **RewardTxRepo** - работа с транзакциями наград (начисления, история, баланс)
- **AchievementRepo** - работа с достижениями (получение, назначение пользователям)

### 2. Интерфейсы сервисов (`internal/core/interfaces.go`)
- **AuthService** - аутентификация (регистрация, логин, токены, валидация)
- **UserService** - управление пользователями (профиль, статистика, streak)
- **LevelService** - работа с уровнями (список, детали, доступность)
- **AttemptService** - прохождение уроков (старт, вопросы, ответы, завершение)
- **RewardService** - система наград (начисления, списания, история)
- **AchievementService** - достижения (проверка, выдача, прогресс)

### 3. HTTP слой (`internal/http/`)
- **types.go** - типы для API ответов, запросов, ошибок
- **router.go** - настройка всех маршрутов с группами
- **middleware.go** - CORS, логирование, аутентификация, rate limiting
- **handlers.go** - все HTTP обработчики для эндпоинтов

### 4. Заглушки реализаций
- **internal/repo/implementations.go** - заглушки всех репозиториев
- **internal/core/implementations.go** - заглушки всех сервисов

## API Эндпоинты

### Аутентификация (публичные)
- `POST /v1/auth/register` - регистрация
- `POST /v1/auth/login` - вход
- `POST /v1/auth/refresh` - обновление токена

### Пользователь (защищенные)
- `GET /v1/me` - информация о себе
- `PUT /v1/me/profile` - обновление профиля
- `GET /v1/me/stats` - статистика пользователя

### Уровни (защищенные)
- `GET /v1/levels` - список всех уровней
- `GET /v1/levels/:id` - детали уровня
- `GET /v1/levels/topic/:topic` - по теме

### Попытки прохождения (защищенные)
- `POST /v1/attempts` - начать попытку
- `GET /v1/attempts` - история попыток
- `GET /v1/attempts/:id` - детали попытки
- `GET /v1/attempts/:id/next` - следующий вопрос
- `POST /v1/attempts/:id/answer` - ответить на вопрос
- `POST /v1/attempts/:id/complete` - завершить попытку

### Награды (защищенные)
- `GET /v1/rewards/balance` - баланс алмазов
- `GET /v1/rewards/transactions` - история транзакций

### Достижения (защищенные)
- `GET /v1/achievements` - все достижения
- `GET /v1/achievements/my` - достижения пользователя
- `GET /v1/achievements/:id/progress` - прогресс по достижению

## Как работать дальше

### Вариант 1: Один человек делает всё
1. Начать с `AuthService` и `UserRepo` - реализовать регистрацию/логин
2. Затем `LevelService` и `LevelRepo` - список уроков
3. Потом `AttemptService` и `AttemptRepo` - прохождение уроков
4. В конце `RewardService` и `AchievementService`

### Вариант 2: Разделить на двоих

**Человек A (Инфраструктура + Auth):**
- Реализовать `UserRepo`, `AuthService`
- JWT токены, хеширование паролейc
- Middleware аутентификации
- Эндпоинты: `/auth/*`, `/me`, `/me/profile`, `/me/stats`

**Человек B (Контент + Прохождение):**
- Реализовать `LevelRepo`, `QuestionRepo`, `AttemptRepo`
- `LevelService`, `AttemptService`
- Эндпоинты: `/levels/*`, `/attempts/*`

**Общие задачи:**
- `RewardService`, `AchievementService` (можно делать параллельно)
- Тестирование интеграции
- Документация API

## Структура файлов

```
backend/
├── cmd/server/main.go          # Точка входа, инициализация
├── config/config.go            # Конфигурация
├── internal/
│   ├── domain/                 # Модели данных
│   ├── repo/                   # Репозитории (доступ к БД)
│   │   ├── interfaces.go       # Интерфейсы репозиториев
│   │   └── implementations.go  # Заглушки реализаций
│   ├── core/                   # Бизнес-логика
│   │   ├── interfaces.go       # Интерфейсы сервисов
│   │   └── implementations.go  # Заглушки реализаций
│   └── http/                   # HTTP слой
│       ├── types.go            # Типы для API
│       ├── router.go           # Маршруты
│       ├── middleware.go       # Middleware
│       └── handlers.go         # HTTP обработчики
└── migrations/                 # Миграции БД
```
